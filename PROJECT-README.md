# EnglishPro v2.0 — серверная версия (Backend + БД + доступ с телефона)

Приложение для репетитора английского: ученики, расписание, финансы, абонементы, соцсети.
Next.js 16 (App Router) + React 19 + Zustand + Tailwind CSS 4 + **Prisma (SQLite) — теперь с настоящим бэкендом**.

## Что нового в v2.0 (доступ с телефона и любых устройств)

Раньше все данные хранились только в localStorage браузера — на телефоне приложение открывалось пустым. Теперь данные живут на сервере в базе данных SQLite (через Prisma ORM) и синхронизируются между устройствами.

1. **Backend и база данных**
   - Next.js API Routes: `/api/auth/*` (регистрация, вход, выход, профиль, смена пароля) и `/api/data` (GET/PUT снапшота данных).
   - БД SQLite через Prisma: таблицы `User` (email + **scrypt-хеш пароля** — пароли больше не хранятся в открытом виде), `Session` (токены сессий) и `UserData` (данные приложения).
   - Сессии — httpOnly-cookie `ep_session` на 30 дней: вход не сбрасывается при перезагрузке.

2. **Синхронизация между устройствами**
   - При входе данные загружаются с сервера; любое изменение автоматически сохраняется на сервер (autosave с дебаунсом ~0.7 с).
   - Один и тот же аккаунт на компьютере и телефоне видит одинаковые данные: учеников, уроки, финансы, абонементы, настройки.
   - При возврате на вкладку данные подтягиваются с сервера (если нет несохранённых изменений).
   - Индикатор синхронизации в меню: «Сохранено · 16:58» / «Сохранение…» / «Ошибка» (например, при потере интернета; после восстановления соединения сохранение повторяется автоматически).

3. **Автоматический перенос старых локальных данных**
   - Если в браузере остались данные старой локальной версии, при регистрации/входе **с тем же email** они автоматически переносятся на сервер (тост «Локальные данные перенесены на сервер»).
   - Если данные не подошли к аккаунту, они не теряются: сохраняется резервная копия браузера, и её можно восстановить в настройках («Синхронизация → Резервная копия браузера → Восстановить»).
   - Экспорт/импорт JSON по-прежнему доступны в настройках; импорт теперь тоже сохраняет данные на сервер.

4. **PWA — установка на телефон как приложение**
   - Добавлен `manifest.json` и иконки: в Chrome на Android — «Установить приложение» / «Добавить на главный экран», на iPhone — «На экран “Домой”» через меню Safari.
   - Приложение открывается в отдельном окне без адресной строки, с фирменной иконкой и цветом темы.
   - Вёрстка адаптирована под телефон: «бургер»-меню, карточки и модальные окна помещаются на экран.

## Как открыть с телефона

1. Запустите приложение (см. «Как запустить») — оно должно быть доступно в интернете (домен/публичный IP, а не только localhost).
2. Откройте адрес на телефоне в браузере → зарегистрируйтесь или войдите в **тот же аккаунт**, что на компьютере.
3. Данные подтянутся с сервера автоматически.
4. (Необязательно) Добавьте иконку на главный экран — приложение будет открываться как установленное.

## Как запустить

Требуется Node.js 18+ (или Bun).

```bash
npm install          # или: bun install (postinstall сам сгенерирует Prisma Client)
npm run setup        # создаст .env, сгенерирует Prisma Client и создаст SQLite-базу db/custom.db
npm run dev          # или: bun run dev
```

Откройте http://localhost:3000

Скрипт `setup` сам создаёт файл `.env` с **абсолютным** путём к базе для вашей машины — работает одинаково на Windows, macOS и Linux, править файл вручную не нужно. База появится в `db/custom.db` (её удобно бэкапить простым копированием).

Продакшен-сборка:

```bash
npm run build
npm start
```

### Если возникает ошибка «@prisma/client did not initialize yet. Please run "prisma generate"»

Prisma Client не был сгенерирован (обычно после распаковки архива без последующего `npm install`). В папке проекта выполните:

```bash
npm run setup
npm run dev
```

Если нужно по шагам (например, проект установлен давно и скрипта `setup` нет в package.json):

```bash
npx prisma generate
```

затем создайте `.env` в корне проекта одной командой (путь подставится автоматически для вашей ОС):

```bash
node -e "require('fs').writeFileSync('.env','DATABASE_URL=file:'+require('path').resolve('db/custom.db').split(String.fromCharCode(92)).join('/')+String.fromCharCode(10))"
```

и создайте базу: `npx prisma db push`.

### Размещение в интернете (чтобы открыть с телефона)

**Вариант 1 — Docker (проще всего, любой VPS):**

```bash
docker compose up -d --build      # соберёт и запустит контейнер
```

Готово: приложение на порту 3000 (снаружи), БД — в томе `englishpro-db` (переживает пересоздание контейнера). Полезные команды:

```bash
docker compose logs -f              # логи
docker compose exec englishpro node scripts/backup-db.mjs   # бэкап БД
docker compose down && docker compose up -d --build        # обновление версии
```

Осталось закрыть портом HTTPS: поставьте Caddy (`caddy reverse-proxy --from app.example.com --to localhost:3000`) — он сам получит сертификат Let's Encrypt.

**Вариант 2 — VPS без Docker (Node.js 18+):**

```bash
npm install
npm run setup
npm run build
npm start                          # слушает :3000, дальше Caddy/Nginx + HTTPS
```

**Вариант 3 — Railway / Fly.io / Render**: подойдут «из коробки» (долгоживущий процесс + постоянный диск для SQLite; DATABASE_URL=file:/data/custom.db на постоянном томе).
**Vercel**: serverless без постоянного диска — для SQLite замените провайдера БД в `prisma/schema.prisma` на PostgreSQL + `npm run db:push` заново; остальной код не меняется.

### Мониторинг и бэкапы

- **Health-check**: `GET /api/health` → `{"status":"ok","db":"up",...}` (используется Docker healthcheck, подходит для UptimeRobot и т.п.).
- **Бэкап БД**: `npm run backup` — консистентный снимок SQLite (VACUUM INTO, безопасен при работающем сервере) в папку `backups/`, хранятся последние 30 копий (настраивается `BACKUP_KEEP`). Для авто-бэкапа добавьте в cron: `0 3 * * * cd /путь/к/englishpro && npm run backup`.
- **Восстановление**: остановите сервер, замените `db/custom.db` нужной копией из `backups/`, запустите сервер.

## Архитектура хранения данных

- **Сервер — источник истины.** Данные приложения (ученики, классы, уроки, финансы, абонементы, настройки) хранятся как версионированный JSON-снапшот на пользователя в таблице `UserData`. Такая схема дает синхронизацию «без потерь» при любой эволюции полей и лёгкий бэкап (строка БД = полный слепок данных).
- **Клиентский store** (Zustand) содержит всю бизнес-логику — она не изменилась: списания, абонементы, штрафы, балансы считаются как раньше. Меняется только слой сохранения: вместо записи в localStorage — PUT `/api/data`.
- **localStorage остаётся офлайн-кэшем**: мгновенная загрузка при открытии и защита от потери при обрыве сети (несохранённые изменения досылаются при восстановлении соединения).
- Тема (тёмная/светлая) — локальная настройка устройства, между устройствами не синхронизируется.

## Безопасность

- Пароли хранятся только в виде scrypt-хеша с солью (node:crypto), проверка — за константное время.
- Сессии: 256-битный случайный токен в БД + httpOnly, SameSite=Lax cookie; выход удаляет сессию.
- Все API-роуты данных требуют валидную сессию; чужие данные недоступны.

## Функциональность (история версий)

1. **Ученики**: карточки с балансом, ставкой, телефоном/email, датой рождения, заметками, фото, архивом; поиск.
2. **Занятия**: календарь (месяц/неделя/день), расписание, повторяющиеся уроки, посещаемость группы, отмены со штрафами, перенос.
3. **Абонементы** (v1.0–1.1): создание (4/8/12/16 или своё число), списание стоимости с баланса (возможен минус), шкала прогресса на карточке, статусы (Активен/Будущий/Заморожен/Недействителен/Архив), заморозка, авто-архив недействительных, возврат занятий при удалении; запрет пересечения периодов действия двух абонементов одного ученика (при создании и редактировании).
4. **Финансы**: доходы/расходы по категориям, автоматические записи (оплата урока, покупка/возврат абонемента, штрафы, пополнения баланса), месячные отчёты.
5. **Классы и группы**: групповые занятия, стоимость на ученика, статистика.
6. **Социальные сети ученика**: ВКонтакте, Telegram, MAX — добавление и редактирование только в настройках карточки ученика (вкладка «Ученик» редактора; у родителя — во вкладке «Родитель»), на карточке ученика — значки-кнопки добавленных сетей с открытием профиля; валидация формата каждой сети.
7. **Настройки**: профиль (имя/email/фото), смена пароля, экспорт/импорт JSON, очистка данных, тема.
8. **Кабинет администратора**: пользователи (создание, роли, архив, имперсонация, режим управления), статистика по учителям, журнал аудита, настройки с профилем и карточкой «Почта».
9. **Почта (этапы 1–2)**: SMTP-шлюз с тестом отправки; при создании аккаунта — автоматическое приглашение с временным паролем на почту (с фолбэком на ручную передачу) и обязательной сменой пароля при первом входе.
10. **«Забыли пароль?» (этап 4)**: самостоятельное восстановление по письму — ссылка на экране входа → письмо со одноразовой ссылкой (живёт 60 минут) → страница нового пароля; смена пароля отзывает все сессии аккаунта. Подробности — в разделе «Восстановление пароля».
11. **Напоминания ученикам и родителям (этап 4)**: письмо о предстоящем занятии ученику и/или родителю перед каждым занятием — общие настройки по умолчанию (выключено) и личные настройки ученика (шестерёнка «Настройки» на карточке). Общий ползунок — главный выключатель: выключен → письма не уходят, даже при включённых личных настройках. Удаление учеников — только из архива.

## Почта (SMTP)

Приложение умеет отправлять письма через SMTP (по умолчанию — Яндекс). На этом построены тестовая проверка и будущие сценарии: пароль на почту при создании аккаунта, напоминания о занятиях, квитанции.

**Настройка (5 минут):**
1. Включите двухфакторную аутентификацию на ящике Яндекса.
2. Откройте id.yandex.ru → Безопасность → Пароли приложений → создайте пароль для «Почты».
3. Заполните в `.env` (локально) и/или в `.env` рядом с `docker-compose.yml` (на сервере): `SMTP_USER` (ваш ящик) и `SMTP_PASS` (пароль приложения). Хост/порт уже заданы (`smtp.yandex.ru:465`), при желании переопределите `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM` (подпись отправителя, например `EnglishPro <thomasage@yandex.ru>`).
4. Перезапустите приложение (`npm run dev` или `docker compose up -d --build`).
5. Проверка: Кабинет администратора → Настройки → карточка «Почта» → кнопка «Отправить» — тестовое письмо придёт на вашу почту (первые письма могут попадать в «Спам» — нажмите «Не спам»). Там же виден статус: настроена почта или нет.

**Приглашение при создании аккаунта:** при создании аккаунта админом (Кабинет → Пользователи → «Добавить пользователя») по умолчанию включён режим «Выслать пароль на почту»: сервер сам генерирует временный пароль, сохраняет его хеш и отправляет письмо с логином и паролем; админ пароль не видит. При первом входе пользователь обязан сменить пароль. Если письмо отправить не удалось, аккаунт всё равно создаётся, а пароль показывается админу один раз для ручной передачи. Режим «ввести пароль вручную» остался как опция.

Технически: `src/lib/mailer.ts` — единая точка отправки (Nodemailer, ленивый транспорт, письмо никогда не ломает основную операцию), API `/api/admin/mail-test` (статус + тестовая отправка, только для админов). Креды читаются только из переменных окружения и никогда не попадают в код, логи и ответы API. Образец переменных — `.env.example` (включая необязательные `APP_URL` — публичный адрес для ссылок в письмах — и `CRON_SECRET`).

## Восстановление пароля («Забыли пароль?»)

Если пароль забыт, администратор не нужен: на экране входа есть ссылка **«Забыли пароль?»**. Введите почту аккаунта — придёт письмо с кнопкой «Задать новый пароль». Ссылка живёт **60 минут** и срабатывает **один раз**; новый запрос письма аннулирует прежнюю ссылку. После успешной смены все прежние сессии аккаунта завершаются — входите с новым паролем. Письма нет? Проверьте «Спам».

Ссылка из письма открывает тот же адрес приложения с параметром `?reset=...` — экран входа временно заменяется формой нового пароля (два поля: пароль и повтор). Пункт «Изменение пароля» в настройках работает по-прежнему — для тех, кто помнит текущий пароль.

Безопасность: в базе хранится только sha256-хеш токена (утечка дампа не даёт восстановить ссылки); ответ API всегда «успешный» и не раскрывает, какие адреса зарегистрированы; ограничение частоты — не больше 3 писем на адрес за 15 минут; заархивированный аккаунт восстановить пароль не может. Технически: `src/app/api/auth/forgot-password/route.ts` (запрос письма), `src/app/api/auth/reset-password/route.ts` (установка нового пароля), `src/components/ep-reset-password.tsx` (форма из письма), модель `PasswordResetToken` в схеме БД.

## Напоминания о занятиях

Приложение само присылает педагогам на почту: **сводку на день** (все занятия дня таблицей), **напоминание перед занятием** (точечно о каждом занятии за выбранное число минут до начала) и **план на неделю** (занятия на 7 дней по дням в выбранные дни). Отменённые занятия пропускаются, в «пустой» день письма нет.

**Встроенный планировщик включён по умолчанию** (REMINDER_BUILTIN=1): приложение само проверяет занятия каждые 5 минут и шлёт письма — ничего настраивать не нужно. Сводки уходят в окне 3 часа после назначенного времени (первый же тик внутри окна отправляет письмо, повторные гасятся дедупликацией); если сервер был перезапущен, письма всё равно уйдут, когда он поднимется в окне.

**Каждый педагог сам управляет своими письмами** — в учительском кабинете: Настройки → карточка «Уведомления о занятиях». У каждого из пяти уведомлений — **своя шестерёнка** рядом с ползунком:
- **Сводка на день** — во сколько присылать расписание на текущий день (по умолчанию 07:00);
- **Напоминание перед занятием** — за сколько минут до начала напоминать (5–1440, по умолчанию 60);
- **План на неделю** — время (по умолчанию 07:00) и дни недели, когда присылать план (по умолчанию понедельник);
- **Напоминание ученику** — письмо ученику перед его занятием (по умолчанию выключено, окно 5–1440 минут, дефолт 60);
- **Напоминание родителю** — письмо родителю перед занятием ученика (по умолчанию выключено, окно 5–1440 минут, дефолт 60). Оба ползунка этого раздела — главные выключатели: выключено → письма не отправляются, даже ученикам со «Своими настройками».

Письма ученику и родителю уходят на адреса из карточки ученика (у родителя — со вкладки «Родитель»); у кого email не указан — письмо пропускается. В письмах ученику и родителю заметки педагога не показываются. Для групповых занятий каждый участник получает своё письмо.

**Настройки строго индивидуальны** — у каждого аккаунта свои время, дни и минуты; при переключении между аккаунтами (вход, «Управление аккаунтом» у администратора) они не переносятся и не смешиваются: каждому — свои. Связка дней и ползунка недельного плана: если в шестерёнке не выбран ни один день — недельный план отключается, ползунок «План на неделю» автоматически уходит влево; выбор первого дня снова включает его (включение ползунка без дней подставляет понедельник).

**Личные настройки ученика (шестерёнка «Настройки» на карточке).** На каждой карточке ученика, слева от «В архив», есть шестерёнка «Настройки» — компактное окно настроек ученика (в будущем здесь появятся и другие настройки). Сейчас в нём один раздел — «Напоминания о занятиях» с двумя режимами:
- **«Как у всех»** — действуют общие настройки аккаунта из карточки «Уведомления о занятиях» (в окне видна сводка: ученику/родителю — включено и за сколько минут);
- **«Свои настройки»** — свои тумблеры «Слать ученику»/«Слать родителю» и своё окно в минутах. Действуют при включённом общем ползунке: если общий выключен, письма не уходят никому (в окне настроек ученика в этом случае показывается предупреждение). При включённом общем можно выборочно отключить/включить отдельных учеников или задать другой тайминг.

Если у ученика заданы свои настройки, на шестерёнке появляется акцентная точка — так видно, кто на индивидуальном режиме, не открывая окно. Все изменения сохраняются сразу.

**Удаление учеников — только из архива.** У активной карточки кнопки «Удалить» больше нет: сначала ученика нужно отправить в архив (с подтверждением), в архиве появятся «Вернуть из архива» и «Удалить» (с подтверждением: история проведённых/отменённых уроков сохраняется). Массовое удаление тоже доступно только во вкладке «Архив».

Настройки хранятся в данных аккаунта и действуют на всех устройствах; время московское (REMINDER_TIMEZONE).

**Внешний крон (необязательно):** если отключить встроенный (REMINDER_BUILTIN=0), можно слать по расписанию через crontab:
```cron
0 7 * * *   curl -s "http://localhost:3000/api/cron/reminders?type=daily&secret=СЕКРЕТ"
*/10 * * * * curl -s "http://localhost:3000/api/cron/reminders?type=hourly&secret=СЕКРЕТ"
0 7 * * 1   curl -s "http://localhost:3000/api/cron/reminders?type=weekly&secret=СЕКРЕТ"
```
(или через внешний сервис типа cron-job.org, бьющий по `https://ваш-домен/api/cron/reminders?...`). Персональные окна и дни педагогов соблюдаются при любом способе запуска — их проверяет сам движок; для нестандартных времён сводок чаще вызывает hourly/daily-типы (тик каждые 5 минут покрывает всё, минимальное окно напоминания — 5 минут).

**Проверка вручную:** `http://localhost:3000/api/cron/reminders?type=daily&secret=СЕКРЕТ` — JSON с числом учителей и отправленных/пропущенных писем; `&dry=1` — посчитать, ничего не отправляя. Секрет задаётся в `.env` (CRON_SECRET, образец в `.env.example`).

Технически: `src/lib/ep-reminders.ts` — разбор снапшотов и настроек уведомлений (валидация времени/дней/минут, дефолты для старых снапшотов), время в заданном поясе (Intl, сервер может жить в UTC), построение писем; `src/lib/ep-reminder-engine.ts` — обход учителей, персональные окна отправки, дедупликация (маркеры `REMINDER_SENT` в аудите — письмо не уйдёт дважды), учёт настроек аккаунта; `src/lib/ep-scheduler.ts` + `src/instrumentation.ts` — встроенный планировщик; `src/app/api/cron/reminders/route.ts` — защищённый секретом роут для внешнего крона. Сбой SMTP не ломает обход и повторяется на следующем тике (`REMINDER_ERROR` в аудите).

## Частые вопросы

**Перенёсся ли мой старый аккаунт?** Аккаунты старой версии хранились только в браузере. Зарегистрируйтесь тем же email, что был в старой версии, — данные перенесутся автоматически (или восстановите их через настройки).

**Можно ли работать без интернета?** Приложение откроется из кэша и покажет последние данные, но для сохранения изменений и входа нужен интернет. При обрыве изменения не теряются и отправятся после восстановления связи.

**Что если войти с двух устройств одновременно?** Изменения с последнего сохранённого устройства имеют приоритет (last-write-wins). Для одного репетитора это безопасно; перед важными изменениями нажмите «Обновить» в настройках, чтобы забрать свежие данные.
